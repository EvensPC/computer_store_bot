# Telegram-бот каталога компьютерных товаров

Готовый проект на **Python + aiogram 3 + SQLite**. Главное меню оформлено как на вашем скриншоте: вертикальные кнопки с разделами («Блоки питания», «Видеокарты» и т. д.), поиск, профиль, «Стать оптовиком». После выбора раздела открываются подгруппы, список товаров, карточка и сравнение цен.

**Источники подключены в настройках проекта:**

- **Прайс 379 — основной каталог:** [Google Sheets](https://docs.google.com/spreadsheets/d/1YloYvrGUqWY45khtZUVKbfmAupR1PotJhXUTTTP--JA/edit#gid=298640172), `gid=298640172`.
- **Прайс 482 — цены для сравнения:** [Google Sheets](https://docs.google.com/spreadsheets/d/1aI1SuXZ2PfiKL4d4neY0xYRuWSHybS0PD1z3rFOnnM8/edit?gid=0#gid=0), `gid=0`.

⚠️ В этой среде реальную выгрузку CSV из Google Sheets получить не удалось, поэтому импорт **живых** таблиц и количество совпадающих товаров пока не проверены. В веб-представлении прайса 482 видны строки без обычной шапки: артикул, товар и цена; для такого формата добавлено распознавание. Если Google-таблица имеет другую структуру, назначьте столбцы вручную. В архиве нет выдуманных реальных цен.

## Что умеет бот

- Главное меню на обычной Telegram-клавиатуре, максимально близкое к примеру (точные цвета и фон задаёт клиент Telegram).
- Категории → подкатегории → товары → карточки с названием, артикулом и ценой.
- Для обычного пользователя — розничная цена, для одобренного оптовика — оптовая и розничная. Если какого-то типа цены в таблице нет, бот пишет «не указана», **не придумывает цену**.
- Поиск по названию и артикулу, постраничный вывод.
- Заявка на оптовый доступ, уведомления администраторам, одобрение/отклонение.
- `/admin`: текущие заявки, вся история, все оптовики, отзыв доступа, выгрузка JSON и CSV, обновление таблицы и просмотр заголовков Google Sheets.
- **Сравнение 379 ↔ 482**: артикул → при отсутствии совпадения артикула полное нормализованное название. При разных названиях и одинаковых артикулах показывает предупреждение «проверьте название». Показывает обе цены и разницу в рублях и процентах.
- Возможность отправить фото из столбца `Фото` (HTTPS), а при наличии ссылки на **конкретную** карточку товара DNS — попытаться получить `og:image` из этой карточки. Автоматический поиск по сайту DNS не гарантируется и обход блокировок не реализуется.
- Синхронизация Google Sheets при запуске, далее каждые 15 минут и по кнопке из админ-панели. При ошибке скачивания/разбора сохраняет предыдущий каталог.
- Отдельный реестр оптовиков `data/wholesalers.json`, заявки и каталог в `data/bot.sqlite3`. Код не перезаписывает эти файлы во время обновлений.

## 1. Установка на компьютере (Windows / Linux / macOS)

Установите Python **3.11 или 3.12** и создайте Telegram-бота через [@BotFather](https://t.me/BotFather). Получите токен бота. Узнайте свой числовой Telegram ID через [@userinfobot](https://t.me/userinfobot) (или командой `/id` после запуска).

**Linux / macOS:**

```bash
cd computer_store_bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

**Windows (PowerShell):**

```powershell
cd computer_store_bot
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env`, замените `PASTE_TOKEN_FROM_BOTFATHER` настоящим токеном и укажите числовой `ADMIN_IDS` (можно несколько через запятую). Таблица и `gid` уже указаны верно, их менять не нужно.

Запуск:

```bash
python run.py
```

В Telegram отправьте боту `/start`. После выбора любой группы появятся подкатегории. Клавиатура главного меню останется внизу чата. Админ-панель: `/admin`.

## 2. Как дать боту доступ к Google-таблице

### Способ А: таблица доступна для чтения по ссылке

В Google Sheets нажмите «Настроить доступ» → «Общий доступ» → «Все, у кого есть ссылка» → «Читатель». Тогда бот использует CSV-экспорт Google без ключей. **Это делает прайс доступным всем, у кого есть ссылка**, поэтому способ подходит не для конфиденциальных таблиц.

### Способ Б: таблица приватная (рекомендуется для коммерческого прайса)

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект и включите **Google Sheets API**.
2. Создайте сервисный аккаунт (Service Account) и скачайте его JSON-ключ. Не выкладывайте ключ в чаты или репозиторий.
3. В **обеих Google-таблицах (379 и 482)** добавьте email `client_email` из JSON-файла **как читателя**. Если чужой лист нельзя расшарить сервисному аккаунту, он должен быть доступен для CSV-экспорта по ссылке без авторизации, а для приватного основного листа нужен отдельный доступ.
4. Создайте папку `secrets` рядом с `run.py`, положите файл, например, `secrets/google-service-account.json`.
5. Добавьте в `.env`:

```env
GOOGLE_SERVICE_ACCOUNT_FILE=/полный/путь/к/computer_store_bot/secrets/google-service-account.json
```

Для Docker используйте путь `/app/secrets/google-service-account.json` (папка `secrets` монтируется с хоста, см. ниже).

Для доступа к **обеим** таблицам нужны права на чтение. Одного ID без доступа может быть недостаточно. Если при синхронизации ошибка `403`, проверьте, с кем именно поделились таблицей.

## 3. Как сопоставить реальные столбцы вашего прайса

После запуска зайдите в `/admin` → **«Посмотреть столбцы Google-таблицы»**. Если заголовки нестандартные или располагаются не в первой строке, создайте файл `data/column_map.json`. Пример есть в `examples/column_map.example.json`:

```json
{
  "header_row": 1,
  "columns": {
    "sku": "Артикул",
    "name": "Наименование",
    "category": "Группа",
    "subcategory": "Подгруппа",
    "retail_price": "Розница",
    "wholesale_price": "Опт",
    "dns_url": "Ссылка DNS",
    "photo_url": "Фото"
  }
}
```

Здесь указаны **примерные** заголовки, не подтверждённые содержимым вашей таблицы. Используйте реальные. Если цены находятся, например, в столбцах `G` и `J`, можно написать `"retail_price": "G"` и `"wholesale_price": "J"`. Для номера столбца используйте `"#7"` (считая с 1). Если поле не существует, **удалите соответствующую строку** из сопоставления, чтобы бот не пытался его прочитать. Неизвестные поля можно не указывать. После сохранения нажмите **«Обновить Google-таблицу»** в `/admin`.

Валидатор требует название и **как минимум один** тип цены. Если нет розничной или оптовой колонки, отсутствующий тип **остаётся пустым**. Если нет артикула, товар получает только скрытый технический ключ для работы кнопок, а в карточке будет «Артикул не указан в таблице». Если не указаны группы, бот пытается определить их по названию; это эвристика, которую лучше заменить явными столбцами `Группа` и `Подгруппа`.

Если группа указана строкой-разделителем без цены, бот попытается перенять название для следующих товаров. Эта возможность не заменяет правильную структуру таблицы.

## 4. Сравнение прайса 379 с прайсом 482

**Уже прописано в `.env.example`** (и есть те же значения по умолчанию в `app/config.py`):

```env
# Главный каталог: прайс 379
GOOGLE_SHEET_ID=1YloYvrGUqWY45khtZUVKbfmAupR1PotJhXUTTTP--JA
GOOGLE_SHEET_GID=298640172

# Второй источник: прайс 482
GOOGLE_OTHER_SHEET_ID=1aI1SuXZ2PfiKL4d4neY0xYRuWSHybS0PD1z3rFOnnM8
GOOGLE_OTHER_GID=0
SYNC_INTERVAL_MINUTES=15
```

Кнопка «💰 Сравнить цены» в карточке товара показывает **цену из прайса 379**, **цену из прайса 482** и **разницу** (в рублях и процентах). Для розничного покупателя берётся розничная цена 379; для одобренного оптовика — оптовая цена 379. **Цена 482 одна и та же справочная для обоих типов клиентов**: она не объявляется ни оптовой, ни розничной, поскольку это не подтверждено второй таблицей. Цена 379 для оптовика никогда не раскрывается обычному покупателю. При отсутствии оптовой колонки 379 бот напишет «не указана», не выдумывая её.

Бот сначала соединяет записи по **одинаковому артикулу** (игнорируя регистр/пробелы). Если такого артикула нет, он ищет **строго совпадающее название после нормализации** (без приблизительной похожести и только если совпадение уникально). Если артикулы одинаковые, но названия различаются, бот помечает такую цену «проверьте название!», поскольку внутренние коды двух организаций могут различаться. При ненадёжных совпадениях цена 482 **не подставляется**.

### Если прайс 482 без строки заголовков

Второй прайс может содержать вводные строки и заголовки разделов. Бот умеет распознавать такой лист: первый столбец — артикул, второй — название, а столбец с ценой определяется по числовым значениям. При необходимости откройте `/admin` → **«Посмотреть начало прайса 482»** и укажите расположение колонок в `data/column_map.json`, например:

```json
{
  "header_row": 1,
  "columns": {},
  "other_header_row": 0,
  "other_columns": {
    "sku": "A",
    "name": "B",
    "price": "C"
  }
}
```

Здесь `C` — **пример**, а не подтверждённый столбец живого прайса. Если цена находится в `D`, замените `C` на `D`. При обычной шапке (`Артикул`, `Наименование`, `Цена`) ручная привязка не требуется. Если прайс 379 тоже без шапки, бот попробует аналогично найти артикул, название и **одну розничную** цену; он не выдаёт второй числовой столбец за оптовую цену без явной привязки в `columns`.

После любого изменения нажмите `/admin` → **«Обновить Google-таблицу»**. В ответе будет количество товаров 379 и успешно сопоставленных цен 482. Оригинальные товары 482 без надёжного соответствия в 379 не добавляются в каталог.

При ошибке скачивания или разбора новая загрузка **не стирает** предыдущий каталог и реестр оптовиков. Для живого обновления требуется доступ к обоим листам и подключение сервера к Google Sheets.

## 5. Фото товаров с DNS

Лучше всего добавить в вашу Google-таблицу отдельный столбец `Фото` с прямой ссылкой `https://...` (её Telegram сможет получить). Альтернативно можно добавить `Ссылка DNS` с URL конкретной карточки товара вида `https://www.dns-shop.ru/product/...` — бот попытается извлечь `og:image` страницы, но DNS может не отдать изображение из-за защиты или изменений сайта. Фото необязательно: при его отсутствии будет обычная карточка текстом. Автоматически сопоставлять товары с DNS **по одному названию** в этом проекте не предусмотрено из-за возможных ошибок сопоставления и ограничений доступа сайта.

## 6. Оптовики и админ-панель

Пользователь нажимает **«🤝 Стать оптовиком»** (либо запрашивает доступ из профиля). Заявка попадает в SQLite и уведомление уходит всем ID из `ADMIN_IDS`. Администратор выбирает **«✅ Одобрить»** или «❌ Отклонить». При одобрении ID пользователя, имя, username, дата и ID администратора атомарно записываются в **отдельный документ `data/wholesalers.json`**. После этого оптовая цена автоматически открывается при посещении карточки (даже если пользователь перезапустил Telegram).

В `/admin` есть полный список оптовиков с пагинацией, история всех заявок, отзыв оптовых прав и скачивание реестра в **JSON / CSV для Excel**. Список оптовиков хранится отдельно от кода; историю заявок хранит база `data/bot.sqlite3`.

**ОБЯЗАТЕЛЬНО сохраняйте папку `data/` при обновлении!** Не удаляйте её, не заменяйте пустой папкой и не развёртывайте на эфемерном диске без постоянного тома. Для переноса на другой сервер скопируйте **всю папку `data`**, особенно `wholesalers.json` и `bot.sqlite3`. В архиве исходного кода **нет пустого `wholesalers.json`**, который мог бы затереть ваш реестр. Регулярно делайте резервные копии; сведения о покупателях — персональные данные.

## 7. Запуск через Docker (удобно на VPS)

Скопируйте `.env.example` в `.env`, заполните токен и `ADMIN_IDS`.

```bash
docker compose up -d --build
docker compose logs -f bot
```

Данные всегда находятся в `./data` на вашем сервере (`./data:/app/data`). Это сохранит оптовиков, заявки и каталог после `docker compose up -d --build` и перезапуска контейнера. Если используется ключ Google, поместите его в `./secrets/google-service-account.json`, добавьте в `.env`:

```env
GOOGLE_SERVICE_ACCOUNT_FILE=/app/secrets/google-service-account.json
```

**Не используйте** `docker compose down -v`, если в конфигурации когда-либо появятся именованные тома с рабочими данными. Папку `./data` не удаляйте.

## 8. Проверка без Telegram и без Google

В проекте есть 10 автономных тестов импорта, разбора прайсов без шапки, сопоставления 379 ↔ 482, заявок на опт и сохранения доступа между перезапусками:

```bash
python -m unittest discover -s tests -v
```

Файлы `examples/*.csv` содержат **исключительно вымышленные тестовые товары** и не подгружаются автоматически.

```text
│   ├── database.py              # SQLite, реестр wholesalers.json
│   ├── catalog.py               # порядок категорий, подгруппы
│   ├── keyboards.py             # меню, списки, карточки
│   ├── dns_photos.py            # попытка получить фото с URL DNS
│   └── config.py                # настройки
├── data/                        # НЕ удалять при обновлениях
│   ├── wholesalers.json         # создаётся автоматически, НЕ в архиве
│   ├── bot.sqlite3              # создаётся автоматически
│   ├── products.csv             # локальная копия Google Sheets
│   ├── other_prices.csv         # второй прайс
│   └── column_map.json          # необязательная настройка столбцов
├── examples/                    # только демонстрационные CSV/JSON
└── tests/
```

**Статус проекта:** код собран и автономные тесты пройдены. Реальный запуск Telegram-бота, подключение к вашему Google-аккаунту, фактический формат вашей таблицы и доступность DNS **не проверены**, поскольку не предоставлены токен/доступ к приватной таблице. После выдачи доступа и настройки колонок бот сможет загрузить реальные данные.
